Siglum

A merge gate you can prove.

A green check only tells you a check ran. Siglum proves the validation actually happened on the exact code being merged, under rules the author couldn't edit, and saves it as a proof anyone can verify offline.

THE GAP

A green check means a check finished. It doesn't mean the validation was real.

WHY IT LEAKS

Three ordinary CI facts open the gap.

1 · It only sees the name

The gate trusts that a status called ci finished. It never checks what actually ran behind it.

2 · The PR edits its own gate

If the workflow, test command, scanner config, or a suppression lives in the PR, the author can weaken it.

3 · Silence looks like success

Skips, path filters, continue-on-error, and empty artifacts can all leave a green-looking box.

THE ATTACK · MIASMA

The attacker doesn't forge anything. They poison the evidence the check runs on.

Nothing is hacked. The check is green. The validation never happened.

THE MOVE, IN ONE DIFF

The author changes the thing that grades the author.

One PR, two changes

The same branch asks to merge code and edits the workflow that says whether that code is safe to merge.

The lock is on the inside of the door.

THE GUARANTEE

Four properties. Each kills one way the green check lies.

Recomputed from evidenceSiglum recomputes the verdict itself. A result that's just handed to it gets rejected.
stops: “here, take this green status.”
Fail-closedSkipped, errored, or absent evidence is never a pass.
kills: silently dropping the scanner.
Change-boundTied to the exact commit being merged, including the merge-queue candidate.
stops: approve A, merge B.
IndependentGate-critical checks run where the PR can't edit them.
kills: editing the gate in your own PR.

THE CENTERPIECE

The PR can produce evidence. It can't decide the outcome.

The author hands over the evidence. A separate job decides what it means.

SIGSTORE ECOSYSTEM

Where Siglum sits, and what it reuses.

Green is the one piece Siglum adds (the validation attestation). Blue is the Sigstore it builds on.

THE GAP

Sigstore proves who signed it. It doesn't check the claim was earned.

Sigstore and SLSA already give you

A keyless signer identity (Fulcio), a public transparency log (Rekor), a signature over whatever bytes you hand it (Cosign), and a record of how an artifact was built (SLSA).

What's still missing

A trustworthy verdict that the change was actually validated: computed from evidence, fail-closed, and tied to the exact commit. Plus a gate that blocks the merge when that verdict isn't there.

Sigstore will sign whatever you give it. Siglum makes the thing being signed worth trusting, and blocks the merge when it isn't there.

The proof outlasts the CI run.

HONEST BOUNDARY

Siglum proves the validation happened. It doesn't promise the code is good.

It proves

The declared validators ran to completion over a specific change, under a policy anchored to the base and independent of the author, and the verdict recomputes from the pinned evidence.

It does not claim

That your tests are meaningful, your code is safe, or your dependencies are sound. It also can't stop a compromised org admin from redefining trust.

A gate that overclaims is just another green badge, so we're clear about where the line is.

CLOSE

Make “this change was validated” a fact anyone can verify.

Open source. GitHub-first. Built on Sigstore, in-toto, and SLSA conventions. No long-lived keys, no vendor dashboard to trust, no data leaving the org.

WHOLE PRODUCT

Siglum doesn't scan your code or give you a dashboard. It records that the validation happened.

ARCHITECTURE

Trust boundaries are the architecture.

CORE

The core has no clock, no network, no signer.

EvidenceBundle ──▶ Assessment

Assessment = verdict + coverage + independence
           + merge_eligible + coverage_gaps + decision_hash

That purity is why replay works. Everything external is either evidence in, or signed output.

VERDICT

The verdict is calculated from the evidence.

merge_eligible = verdict == PASS and coverage == FULL and independence != UNMET

OUT OF SCOPE

Siglum stops a malicious contributor. It can't stop an org that redefines its own trust.

Out of scope: a compromised org admin, ruleset-bypass members, control of the org-pinned workflow ref, a compromised GitHub App or Sigstore identity, or a release workflow that chooses not to verify.

Being clear about that boundary is what keeps the proof honest.

TWO TIERS

Dry-run for feedback. Sealed for the guarantee.

Dry-run

Runs in your normal CI. Shows the verdict, silent skips, and policy gaps before you wire the protected gate.

authoring · adoption · fast feedback

Sealed

Org-controlled job outside the PR's reach. Verified OIDC identity, signed attestation, base-anchored policy.

the Miasma defense

Dry-run just shows you what the verdict would be. The real protection comes from how Sealed is wired.

CLI

Six commands. That's the whole tool.

$ siglum audit --repo org/repo # find hollow gates
$ siglum policy lint .siglum/policy.toml
$ siglum setup check --repo org/repo # live-install readiness
$ siglum gate run # trusted seal + enforce, in CI
$ siglum release-check --commit "$SHA" --bundle b.json --identity-policy id.toml
$ siglum demo scaffold --out ./demo --repo org/miasma-prevention-demo

The untrusted gather step runs python -m siglum.validators.run; offline verification uses cosign.

POLICY

Policy is code, read from the protected base.

policy_id = "default"
independence_required = true
anchor_paths = [".siglum/policy.toml", ".github/CODEOWNERS", "Makefile"]

[[validators]]
id = "secret-scan"
required = true

[gate_identity]
repository = "your-org/your-repo"
workflow_path = ".github/workflows/siglum-seal-enforce.yml"
protected_refs = ["refs/heads/main"]

Lintable, canonical, hashed, anchored. A PR can propose policy changes, but it can't use them to grade itself.

VALIDATORS

Validators gather evidence. They don't decide the outcome.

Shipped

secret-scan runs in the gather job today. The command validator is built and unit-tested but not yet wired in.

Custom contract

Any tool that emits the stable validator-result JSON + artifact manifest plugs in.

Planned

SARIF ingestion, Semgrep-style static evidence, and dependency or license checks. They fit the contract but aren't built yet.

Gate-critical validators are concrete, pinned, and base-anchored in Sealed mode.

EXCEPTIONS

When someone overrides the gate, it goes into the proof.

Override

Requires actor and reason. Recorded inside the attestation without rewriting the original FAIL. Dispositions need expiry, actor, reason, and stay visible to auditors.

Cannot override

Signing-identity failures and independence gaps are structural. No author-waivable proof.

THE DRILL

A fixture repo built to be poisoned.

The lock the org relies on is produced by a workflow the contributor can rewrite. We reproduce this on a throwaway fixture repo.

THE POISONED PR

One PR neuters the test and plants a secret.

.github/workflows/ci.yml
- run: python -m pytest
+ run: echo "All tests passed"
service/auth.py
+ AWS_ACCESS_KEY_ID = "AKIA…EXAMPLE"

This is exactly what Siglum is built to stop: code and the gate that checks it, changed together in one PR.
